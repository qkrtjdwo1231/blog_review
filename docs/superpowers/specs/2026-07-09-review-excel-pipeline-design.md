# 리뷰 엑셀 병합·분석 파이프라인 설계

- 작성일: 2026-07-09
- 상태: 승인됨 (사용자 승인 완료, 2026-07-09)

## 배경과 목적

사용자는 쿠팡 등에서 상품 리뷰를 Web Scraper(크롬 확장) 도구로 CSV 파일로 수집한 뒤, 그 데이터를 분석해서 블로그 리뷰 글을 작성한다. 문제는 다음과 같다.

1. 리뷰 데이터가 여러 개의 CSV/엑셀 파일로 쪼개져 있다 (별점별로 파일이 나뉘어 있음).
2. 원본 파일에는 구조화된 별점(1~5) 컬럼이 없다 — 별점은 **파일명 규칙**으로만 표현되어 있다.
3. 상품 카테고리마다 리뷰 속성 컬럼이 다르다 (신발: 색상/사이즈, 손풍기: 배터리/무게 등).
4. 블로그 글은 실제 리뷰 원문에 있는 내용만 근거로 써야 하고, 없는 내용을 지어내면 안 된다.

이 파이프라인의 목적은 여러 CSV 파일을 상품 단위로 하나의 엑셀로 병합하고, 별점별 시트로 정리하며, 정량 분석(리스크 점수 등)을 자동 계산해서, 이후 AI(클로드 등)가 이 엑셀 하나만 읽고 블로그 글을 쓸 수 있도록 준비하는 것이다.

## 입력 데이터 규칙

- 위치: `blog` 폴더 바로 아래에 모든 상품의 CSV 파일이 평평하게(flat) 저장된다. 상품별 하위 폴더는 만들지 않는다.
- 파일명 패턴: `<상품접두사><별점숫자>` 뒤에 괄호 파트번호 `(N)` 또는 `-N` 파트번호가 붙을 수 있다.
  - 예: `shoe1 (1).csv`, `shoe1 (2).csv` → 상품 `shoe`, 별점 1
  - 예: `shoe2.csv`, `shoe2-1.csv` → 상품 `shoe`, 별점 2
  - 정규식: 파일명(확장자 제외)에서 `^([가-힣a-zA-Z]+)(\d)` 로 상품 접두사와 별점 숫자를 추출한다. 괄호 `(...)`나 `-` 뒤에 오는 숫자는 파트 번호이므로 별점 추출에 사용하지 않는다.
  - 별점 숫자는 반드시 1~5 범위여야 한다. 범위를 벗어나면 해당 파일은 건너뛰고 경고를 출력한다 (별점 추출 실패로 간주).
- 같은 상품 접두사를 가진 모든 파일을 하나의 그룹으로 묶는다.
- 인코딩: UTF-8. (Windows 콘솔에서 출력 시 한글이 깨질 수 있으나, 이는 콘솔 출력 문제일 뿐 실제 파일 인코딩과는 무관하다. 파일 read/write는 항상 `encoding='utf-8'`을 명시한다.)
- 컬럼 구조는 상품마다 다를 수 있다. 스크립트는 컬럼명을 하드코딩하지 않고, 원본 CSV에 있는 컬럼을 그대로 유지해서 결과 시트에 옮긴다.

## 출력 엑셀 구조

상품 그룹 하나당 결과 파일 하나를 `blog` 폴더에 생성한다: `<상품접두사>_review_analysis.xlsx`

시트 구성:

1. **`요약` 시트**
   - 별점별(1~4점) 리뷰 개수, 비율(1~4점 합계를 분모로 계산)
   - 5점 리뷰 개수 (파일이 있는 경우만, 참고용으로만 표시하고 비율 계산에는 포함하지 않음)
   - 리스크 점수 (계산식은 아래 참조)
   - 리스크 점수 해석 라벨 (0.20 미만 낮음 / 0.20~0.40 보통 / 0.40~0.60 높음 / 0.60 이상 매우 높음)
   - 표본크기 신뢰도 라벨 (아래 참조)

2. **`1점`/`2점`/`3점`/`4점` 시트** (해당 별점 파일이 있는 경우만 생성)
   - 원본 CSV의 모든 컬럼을 그대로 유지 (리뷰 제목, 본문, 날짜, 상품 옵션/속성 컬럼 등)
   - 추가 빈 컬럼 3개: `핵심_보조_태그`, `근거_원문_인용`, `비고` — 스크립트는 이 컬럼을 빈 채로만 만들고 값을 채우지 않는다. 정성 분석은 이후 AI가 실제 리뷰를 읽고 직접 채운다.

3. **`5점` 시트** (파일이 있는 경우만)
   - 원본 컬럼만 그대로 유지, 정성 분석 컬럼 없음 (참고용)

## 리스크 점수 계산식

```
N = n1 + n2 + n3 + n4   (1~4점 리뷰 수 합, 5점 제외)
p1 = n1/N, p2 = n2/N, p3 = n3/N, p4 = n4/N

raw = (4·p1 + 3·p2 + 2·p3 − 1·p4) / 4
리스크_점수 = max(0, raw)
```

가중치: 1점=+4, 2점=+3, 3점=+2, 4점=−1 (5점은 계산에서 완전히 제외)

**4점 가중치를 −1로 정한 근거**: 4점은 "단점은 있지만 감수 가능하다"는 약한 반대 신호이므로 리스크를 소폭 낮추는 게 타당하다. 다만 그 상쇄력이 1~3점의 가중치(2~4)보다 작아야, 4점 리뷰가 많다는 이유만으로 명백한 1점 불만 신호가 쉽게 지워지지 않는다. −1은 이 조건(절댓값 1 < 2)을 만족하는 가장 단순한 값이다.

**0으로 하한을 두는 이유**: 4점 비율이 매우 높으면 raw 값이 음수가 될 수 있는데, 리스크 점수가 음수라는 것은 해석상 의미가 없으므로(사용자가 정의한 리스크 구간표는 0 이상 스케일) 0에서 잘라낸다(clamp).

**4로 나누는 이유**: 모든 리뷰가 1점일 때(p1=1) raw 값이 정확히 1.0이 되도록 정규화해서, 사용자가 정의한 0~1 스케일의 리스크 해석 구간표(0.20/0.40/0.60 기준)와 맞춘다.

**N=0인 경우 (1~4점 파일이 하나도 없고 5점만 있는 경우)**: 0으로 나누는 오류를 피하기 위해 리스크 점수를 계산하지 않고 "계산 불가 (1~4점 리뷰 없음)"로 표시한다.

## 표본크기 보정

리스크 점수 자체는 건드리지 않고, `요약` 시트에 별도 라벨 컬럼으로만 표시한다 (점수 계산과 해석 강도 문구를 분리해서 혼동을 막기 위함).

| N (1~4점 합) | 라벨 | 블로그 작성 시 적용 방식 |
|---|---|---|
| 10 미만 | 표본 매우 부족 | 단정적 서술 금지, "참고 수준"으로만 언급 |
| 10 이상 30 미만 | 표본 부족 | "일반화에 주의" 문구를 함께 서술 |
| 30 이상 | 표본 충분 | 별도 안내 없이 리스크 점수 해석을 그대로 사용 |

N=0(1~4점 리뷰 없음)은 이 표에 포함되지 않으며, 위에서 설명한 대로 "계산 불가"로 별도 표시한다.

## 정성 분석 (핵심/보조 장단점)

- 파이썬 스크립트는 정량 데이터(개수, 비율, 리스크 점수, 표본 라벨)까지만 자동 계산한다.
- 핵심 단점 / 보조 단점 / 핵심 장점 / 보조 장점 태깅과 그 근거가 되는 리뷰 원문 인용은 스크립트가 하지 않는다. 이후 AI가 완성된 엑셀을 직접 열어 리뷰 본문을 읽고, `핵심_보조_태그`와 `근거_원문_인용` 컬럼에 채워 넣는다.
- **정확성 원칙** (반드시 지킬 것): 리뷰 원문에 없는 내용을 추가하거나 사실과 다르게 서술하면 안 된다. 태그를 달 때는 반드시 근거가 되는 실제 리뷰 원문을 `근거_원문_인용` 컬럼에 함께 남긴다. 리스크 점수나 별점 비율은 문제의 존재 여부를 결정하는 게 아니라, 실제 리뷰 본문에서 반복되는 정도를 확인한 뒤 서술 강도를 조절하는 참고 자료로만 쓴다.

## 스크립트 재사용성

- 파이썬 스크립트(pandas, openpyxl 사용 — 둘 다 로컬에 이미 설치되어 있어 추가 설치 불필요)로 작성한다.
- 사용자가 새 상품의 리뷰 CSV를 `blog` 폴더에 추가하면, 스크립트를 다시 실행하는 것만으로 해당 상품의 결과 엑셀이 (재)생성된다.
- 이미 완성된 블로그 글의 원본 CSV는 사용자가 주기적으로 직접 삭제할 예정이므로, 스크립트는 삭제된 파일에 대해 별도 처리를 하지 않는다 (해당 상품 파일이 없으면 그냥 그 상품은 스킵).

## 범위 밖 (Out of scope)

- 실제 블로그 글 작성 자체는 이 파이프라인의 범위가 아니다 (별도 블로그 작성 스킬/세션에서 이 엑셀을 읽어 수행).
- 정성 분석 자동화(AI 판단 없이 규칙 기반으로 태깅)는 하지 않는다 — 정확성 원칙과 상충하기 때문에 의도적으로 제외했다.
- 여러 상품을 하나의 엑셀로 합치는 기능은 없다 — 상품 1개당 결과 파일 1개.
