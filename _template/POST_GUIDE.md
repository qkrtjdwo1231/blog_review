## 2. 제품 폴더에서 읽을 자료
- `product-summary.jpg`: 상품명, 가격, 옵션, 판매자, 스펙 요약 (이미지라 Read로 본다)
- `rating-summary.jpg`: 별점 막대와 속성 만족도(사이즈·소음 등 퍼센트). 읽히면 쓰고 안 읽히면 쓰지 않는다
- `상세-01.jpg` ~ `상세-NN.jpg`: 상세페이지 전체(40% 축소). 기능명·구조명·수치·주의사항·경고문구를 여기서 뽑는다. 장수가 많으면(15장 이상) 상품 설명 부분을 중심으로 읽되, 제품 사양표와 주의사항 구간은 반드시 읽는다
- `<접두사>1.csv` ~ `<접두사>4.csv`: 1~4점 리뷰 각 20건(열: 작성자, 작성일, 별점, 판매자, 상품옵션, 제목, 내용, 도움수). 80건을 전부 읽고 반복되는 칭찬·불만을 센다. Bash로 `python -I -X utf8` 스크립트를 써서 `내용` 열을 출력해 읽는다(UTF-8 BOM, `encoding='utf-8-sig'`. `-X utf8`이 없으면 cp949 출력 오류가 난다. 덤프 파일을 만들면 다른 제품과 겹치지 않게 파일명에 상품번호를 넣는다)
- 별점 건수: `blog/.product-ratings.json`에서 폴더명으로 찾는다(s5~s1, total). 이 숫자를 `ratings`에 그대로 넣는다. 비율은 스크립트가 계산한다

## 3. post-data.json 작성 규칙
- 모든 필드는 예시 JSON과 같은 키를 쓴다. `option_guide`는 색상·사이즈·모델 선택지가 없으면 `null`.
- `product_name`은 소제목에 들어갈 짧은 제품명(브랜드 + 제품군, 15자 안팎).
- `title`은 기준 글처럼 "가격대/제품명 + 별점 수치나 핵심 이슈 + 호기심 문구" 형태. 과장 표현(강력 추천, 인생템, 무조건) 금지.
- `meta_intro`는 3문장 안팎. 제품명과 별점 5점 비율, 총 리뷰 수, 핵심 이슈 1~2개, "3가지 체크포인트" 유도 문장.
- `rating_comment`는 스킬의 시그널 목록(1점>4점·3점, 5점 80% 이상, 1·2점 합 20% 이상, 2점>1점 또는 1점이 2점의 2배 등)을 실제 숫자로 계산해 2~4문장. 매번 다른 표현.
- `analysis`는 상세 이미지에 나오는 정확한 기능명·구조명·수치로 3개. 상세페이지의 주장과 경고문구가 엇갈리면 그 점을 짚는다.
- `pros`/`cons`는 자료에서 확인되는 만큼만(2~4개). 각 body에 후기 인용을 큰따옴표로 2~3개 넣고, 상세 이미지의 주장과 후기 체감을 한 문단 안에서 엮는다. 리뷰 수·구매자 수·평점은 장점 근거로 쓰지 않는다. 제품군 공통 상식 문장은 쓰지 않는다.
- `score_cards`는 5~6행, 별 5개 중 채운 개수로 ★★★★☆ 형식. 첫 1~2행은 잘 맞는 용도, 마지막 2~3행은 안 맞는 용도.
- `checkpoints`는 3개. head는 행동 지시문 한 줄, body는 상세 경고문구나 후기 근거 + 구체적 행동.
- `conclusion`은 2문단(강점 요약 → 주의점과 조건부 추천). `closing_quote`는 조건 + 대상 + 판단 한 문장.
- `cover`의 글자 수 제한: headline_gold 2줄 각 14자 안팎, headline_dark 12자 안팎, sub 90자 안팎, features 3개(title 12자, desc 28자 안팎), summary 3개(각 20자 안팎), key_line은 예시 그대로 두어도 됨, info 7~8개(value 18자 안팎, 줄바꿈 금지), fit/unfit 각 3개(text 12자 안팎). 아이콘은 이모지 1개.
- 직접 확인 못 한 값에는 (후기 기준), (상세 확인 필요)를 붙인다. 지어내지 않는다.
- 말투: "~는데요", "~입니다" 혼용, 독자는 "~분들". 느낌표 남발 금지. 한국어 문장은 마침표로 끝낸다.

